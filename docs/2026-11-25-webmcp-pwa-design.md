# 設計記録：WebMCP対応＋ディズニー旅行向け拡張＋PWA（2026-11-25）

このファイルは「決まったことと経緯」を残す正本。検討過程は残さない。

## 目的

- 2026-12-18〜20 の東京旅行（ディズニーシー中心）で実際に使う。
- 開発手法の実験場：設計〜実装〜テストを AI（Muse）が主導し、人は実アカウント確認・公開可否・最終実機確認だけを行う。どこで人が必要になったかも記録する。

## やること（スコープ）

1. **履歴・公開の整理**（完了：履歴書き換え済み、force push は権限付与待ち）
   - 全履歴から `node_modules` / `dist` を除去（49MB → 約400KB）
   - 個人サンプルの文言（ペットの名前、実旅行日）を履歴内で置換
   - 初期プランを「サンプル」と明示し、私物の表現を除去、README を追加
   - 秘密情報スキャン結果：本物のキー・パスワード・`.env` の混入は全履歴で無し（2026-11-25 確認）
2. **座標なし stop 対応**
   - stop の `lat`/`lng` を任意にする。未設定の場合は別府座標へのフォールバック（現行仕様）を廃止し、地図・ルート線から除外してタイムラインにのみ表示する。
3. **場所ごとの予定表示**
   - 同一座標に複数の stop がある場合、マーカータップでその場所の予定を時刻順に一覧できる。
4. **共有メモ**
   - stop ごとに `memos: [{ id, text, authorEmail, createdAt }]` を持たせる。
   - ログイン済みの閲覧者（公開プランの閲覧者を含む）が追記できる。作成者の `detail`（説明文）とは役割を分ける。
   - WebMCP の `add_memo` からも追記できる。
5. **WebMCP 対応**
   - `document.modelContext` がある場合のみツール登録（無ければ何もしない、既存 UI は無変更）。
   - ツール：`list_plans` / `get_itinerary`（planId、day 任意）/ `get_place_schedule`（planId＋座標または場所名）/ `create_plan` / `add_stop`（地名→既存 geocodePlace で座標取得、失敗時は座標なしで登録）/ `add_memo`。
   - 書き込み系はログイン済みセッションの権限（owner / editor）内でのみ動作する。
6. **PWA 対応**
   - `vite-plugin-pwa` を使わず、手書きの manifest + Service Worker で最小構成にする（依存を増やさない、Pages の base `/TravelPlanner/` 配下で動くこと）。
   - アイコンは既存のプランアイコン絵文字ではなく、単色＋🧳の生成画像を 192/512 で用意する。
   - オフライン時はアプリシェルとキャッシュ済みアセットのみ（Firestore データのオフライン永続化は対象外）。

## やらないこと

- stop の削除・変更の WebMCP 化（誤削除リスク、今回は追加と読み取りまで）
- Firestore ルールの変更（リポジトリ管理外。ただし公開範囲の確認は別途メモする）
- デザインの刷新（新規 UI は既存のシート／チップ／CSS クラス体系に寄せる）

## 受入条件

- AC-1: 座標なし stop を追加しても地図ピンが別府（33.3158, 131.4772）に出ない。タイムラインには表示される。
- AC-2: 同一座標の stop が2件以上ある場所で、その場所の予定が時刻順に一覧できる。
- AC-3: ログインした閲覧者が stop にメモを追記でき、再読み込み後も残り、著者と時刻が表示される。
- AC-4: WebMCP 対応ブラウザで6ツールが登録され、`get_itinerary` が実際のプラン内容を返す。非対応ブラウザでは従来どおり動作する。
- AC-5: PWA としてインストールでき、オフラインでアプリシェルが開く（Lighthouse の installable 相当を手動確認）。
- AC-6: 既存機能（ログイン、プラン CRUD、共有リンク、地図）が壊れていないことをビルド＋主要画面の目視で確認する。
